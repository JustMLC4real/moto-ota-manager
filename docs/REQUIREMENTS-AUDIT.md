# Requirements audit — 1.0.1

The original 25-section specification and subsequent user direction define the scope. Later direction adds measured cross-model Motorola support, English/Dutch presentation, a first-run tour, public release engineering, CDS as the primary detector and one initial scope covering subsequent update actions. Separate confirmations from the original brief are superseded by that initial scoped intent. The prohibition on destructive physical-device testing during development remains.

This is a source/evidence map. Only [BUILD-REPORT](BUILD-REPORT.md) establishes executed build/test results and the identity of delivered files. A software path is not automatically a physically qualified phone update.

| Requirement | Implementation/evidence map | Limit that remains explicit |
|---|---|---|
| Kotlin/Compose Android app and repository | `app`/`core`, checked-in wrapper/configuration, Compose destinations, adaptive navigation, native EN/NL language, appearance, tour, tests and CI | A debug APK and a maintained production-signed release have different signing identities. |
| Motorola models and spoofed properties | `DeviceCapabilities`, measured profile/layout, independent kernel/build namespaces, typed unknown/conflict results | No marketing-name assumption, guessed alias or blanket certification of all Motorola models. Critical APIs/Magisk remain versioned. |
| Historical OTA failure | Preserved source-hash mismatch analysis, original-image/payload comparisons and historical device report | The original server-side `ALREADY_UP_TO_DATE` decision is not proven; no invented permanent ban or counter reset. |
| Device, root, slots and snapshots | Fixed read-only probes, checked boot metadata, actual engine callback, current Magisk runtime, module/space/battery observations | Missing/conflicting readings block critical operations; no diagnostic bootctl initializer, force-merge or arbitrary setting edits. |
| Original stock backup | Streaming raw/gzip validation, full hashes/size/header, OEM-authenticated old/new boot manifest, exact current identity and independent runtime association | Filename, gzip existence, header, SHA1 directory or a patched copy alone is not stock authenticity. |
| Real stock partition action | Scoped immutable plan, full patched backup, fresh source/runtime/safety checks, one-use authority, constrained active `boot`/`init_boot`, fsync and complete readback | Block I/O is not exercised on a phone in development. Power/storage faults and the independent OEM updater remain outside an atomic app transaction. |
| Primary update discovery | Independent source-derived CDS HTTPS client with consent and strict context/target/resource parsing; official updater/local fallback | Internal protocol, not a public supported Motorola SDK. No forced offer, guessed endpoint or assumption that no offer means no rollout. |
| Package/download/import | Controlled resumable HTTPS, private selected-file publication, bounded existing-OEM import, actual whole-ZIP signature and payload validation | Transfer does not prove authenticity or region/source suitability. Legacy OEM staging keeps its separate signed-channel requirement. |
| One initial update intent | `RunAuthorizationPolicy`/store, bound source boot/device/target/package/actions, package narrowing, bounded short permits and app/root durable claims | Unknown technical evidence still stops. Saved intent is not a crash-replay queue or authority for another future target. |
| OTA/Magisk/reboot integration | Durable phase/evidence contracts and reviewed versioned adapter boundaries, with official-app fallback | Runtime access and bootability need device-specific qualification. A shell success, user report or app opening is not independent completion proof. |
| Post-boot completion | Reconcile actual new boot ID, target build/slot, root/Magisk, successful boot, kernel state, modules, snapshots/engine and new stock association | Missing next-update stock proof remains review. Module presence is not module functionality or Wallet/attestation compatibility. |
| Process death and recovery | AtomicFile journal, exact transaction/source binding, durable consumption, recovery under writer lock and no automatic replay/rollback | Corrupt/unknown state is recovery required; never reset it to an empty successful run. |
| Privacy and exports | Allowlisted local EN/NL report, separate consent-only identifiers, encrypted download references, disabled Android backup/transfer, no automatic upload | Real network checks disclose their listed data. Private storage/MACs cannot defeat a separate full-root compromise. |
| Tests and documentation | [TEST-MATRIX](TEST-MATRIX.md) maps all twenty requested scenarios and additional capability/authorization/runtime/UI cases; EN/NL user guides and [manual plan](MANUAL-TESTS.md) | Synthetic, emulator and historical hardware evidence are labelled independently. Current totals must come from actual reports. |
| GitHub-ready first release | Version1.0.1/code5, MIT/NOTICE, templates, pinned Actions, source hygiene scan, signing environment, actual APK verifier and dependency inventory; complete runtime by default, opt-in R8 requires full qualification | Local readiness does not publish a repository or release. No private key, user firmware or OEM decompiled source belongs in the archive. |
| Research and future Android | [Current research](RESEARCH.md), pinned CDS/Magisk/avbroot decisions, separate [roadmap](ROADMAP.md) | API38/Android18, other Magisk versions and changed OEM contracts are not silently approved. |

The complete software delivery requires its current APK, source archive and final concrete logs. Future physical qualification remains a separate activity; it is not silently performed to fill this audit.
